# Originality and Reuse Rules

## Safe to reuse as ideas

- separation of planning, building, and verification
- measurable acceptance criteria
- database-enforced consistency
- idempotent request handling
- concurrency, timezone, and recovery testing
- staged delivery and evidence receipts
- a simple UI that demonstrates the verified backend

## Must be original

- all source code and test fixtures
- product name, narrative, and visual design
- mandate wording and factory documentation
- architecture decisions and tradeoff explanations
- submission answers, slides, and demo script
- BAND room activity and exported evidence
- Git history and test results

## Prohibited

- copying a repository without a compatible license
- renaming another participant's files and submitting them
- copying claimed metrics that were not reproduced
- presenting temporary test fixtures as product files
- claiming a clean autonomous run when a human directed implementation mid-run
- committing API keys, seat credentials, tokens, or private chat exports intended to remain private

## Attribution

If a licensed dependency, official starter, or official test harness is used, record its source, license, version, and the exact boundary between upstream material and original work.
