# Evidence Checklist

## Factory eligibility

- [ ] Every seat has a correctly named mandate with required metadata.
- [ ] A fresh room contains bidirectional seat mentions and responses.
- [ ] The complete room export is saved and contains no exposed secret.
- [ ] Human intervention during the scored run is within event rules.

## Application eligibility

- [ ] The implementation matches the official specification, not a custom substitute.
- [ ] Required Dockerfile and RUN.md files exist in each claimed stage.
- [ ] A clean isolated container builds and serves on the required port.
- [ ] The official harness passes for every claimed stage.
- [ ] The browser UI and any end-to-end flow are directly demonstrated.

## Repository integrity

- [ ] No copied competitor code or wording is present.
- [ ] Upstream starter material is attributed and license-compatible.
- [ ] Secret scan passes on tracked files and history.
- [ ] README claims match current evidence.
- [ ] Branch, commit SHA, test commands, and results are recorded.

## Submission assets

- [ ] Public repository is created only after privacy and secret review.
- [ ] Slides explain the problem, factory, recovery, product, and evidence.
- [ ] Video shows BAND teamwork, repository history, harness output, and demo.
- [ ] Submission form answers are updated from draft to verified facts.
- [ ] Final page confirmation or receipt is preserved.
